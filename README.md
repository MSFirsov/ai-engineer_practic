# RAG с нуля

Система вопросов и ответов по документу, написанная без фреймворков: только `openai` и `numpy`. Цель — разобраться, как устроен RAG (Retrieval-Augmented Generation) изнутри, и улучшать его шаг за шагом.

В качестве документа используется `handbook.txt` — справочник сотрудника вымышленной компании «Тундра Лабс».

## Как это работает

```
ИНДЕКСАЦИЯ (при запуске)                    ЗАПРОС

handbook.txt                                 вопрос
    │ нарезка окнами по 2 предложения          │ эмбеддинг
    ▼                                          ▼
 куски с заголовком раздела                 вектор вопроса
    │ эмбеддинги                               │ косинусная близость
    ▼                                          ▼
 матрица векторов  ─────────────────────▶  top-k кусков
                                               │ промпт: «отвечай только по контексту»
                                               ▼
                                            LLM → ответ
```

1. Каждый абзац документа режется на предложения, и соседние предложения склеиваются по два. К каждому куску приписывается заголовок его раздела, чтобы кусок был понятен без соседей. Почему выбрана такая нарезка, описано в разделе «Нарезка».
2. Каждый кусок превращается в вектор моделью эмбеддингов.
3. Вопрос тоже превращается в вектор, и по косинусной близости находятся самые похожие куски.
4. Найденные куски вставляются в промпт. Модель отвечает только по ним, а если ответа нет, говорит «В документе этого нет».

## Запуск

Нужны [uv](https://docs.astral.sh/uv/) и любой сервер с OpenAI-совместимым API. Я использую [LM Studio](https://lmstudio.ai/) с двумя моделями:

- `google/gemma-4-e4b` — чат-модель;
- `text-embedding-bge-m3` — модель эмбеддингов.

В LM Studio нужно загрузить обе модели и запустить локальный сервер (вкладка Developer → Start Server).

```bash
uv sync
cp .env.example .env
uv run rag.py
```

## Оценка качества

```bash
uv run evaluate.py
```

`evaluate.py` проверяет систему на наборе вопросов с заранее известными ответами:

- **поиск**: для каждого вопроса известна фраза, которая должна быть в нужном куске. Считаются hit@k (доля вопросов, где нужный кусок попал в top-k) и MRR (насколько высоко он стоит);
- **отказы**: на вопросы, ответа на которые в документе нет, модель должна ответить «В документе этого нет».

Текущие результаты (20 вопросов с ответом, 7 без ответа):

| k | hit@k | MRR |
|---|---|---|
| 1 | 0.85 | 0.85 |
| 3 | 0.95 | 0.89 |
| 5 | 1.00 | 0.90 |

Отказов: 7 из 7. Единственный промах поиска при k=3 — «Сколько людей в компании?»: число сотрудников упомянуто одной фразой рядом с рассказом о продукте.

## Нарезка

`evaluate.py` сравнивает несколько стратегий нарезки на одном и том же наборе вопросов:

| Нарезка | Кусков | Ср. длина, симв. | hit@1 | hit@3 | MRR |
|---|---|---|---|---|---|
| абзацы | 33 | 177 | 0.80 | 0.95 | 0.87 |
| предложения | 65 | 100 | 0.85 | 0.90 | 0.88 |
| **окно 2 предложения** | 42 | 143 | 0.85 | 0.95 | 0.89 |
| окно 3 предложения | 35 | 168 | 0.80 | 0.95 | 0.87 |
| разделы | 13 | 415 | 0.80 | 1.00 | 0.88 |
| окно 2 с перекрытием (шаг 1) | 65 | 137 | 0.95 | 0.95 | 0.95 |

Выводы:

- **Предложения** точнее находятся по конкретному вопросу, но теряют контекст: кусок «Это дни, когда...» непонятен без соседнего предложения.
- **Разделы** дают hit@3 = 1.00 только за счёт размера: три куска — это почти четверть документа. Поиск становится размытым, а в промпт попадает много лишнего.
- **Окно из 2 предложений** выбрано по умолчанию как компромисс между точностью и контекстом.
- **Перекрытие** дало лучшие цифры, но каждое предложение лежит в индексе дважды. Соседние окна почти совпадают и могут занять весь top-k, вытеснив другие нужные куски. Пока оно оставлено как эксперимент.

## Настройки

Задаются в `.env`:

| Переменная | Назначение | По умолчанию в `.env.example` |
|---|---|---|
| `OPENAI_BASE_URL` | адрес API | `http://localhost:1234/v1` (LM Studio) |
| `OPENAI_API_KEY` | ключ API | `lm-studio` (LM Studio его не проверяет) |
| `CHAT_MODEL` | модель для ответов | `google/gemma-4-e4b` |
| `EMBED_MODEL` | модель эмбеддингов | `text-embedding-bge-m3` |

Чтобы подключить облачного провайдера, достаточно поменять эти значения.
